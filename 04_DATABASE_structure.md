# 04 — DATABASE STRUCTURE (P2)

```
database/
├── schema.md            # every table/field/enum/index, generated+reviewed | must equal live DB
├── erd.mmd              # Mermaid ERD from migrations
├── migrations/           # golang-migrate SQL, ONE location (D14 v3) — same versions as v1/v2
│   ├── 0001_core_schema.up.sql / .down.sql            # 13 core tables, UUID PKs, FKs (pgcrypto)
│   ├── 0002_enums_constraints.up.sql / .down.sql     # PG enums + CHECKs
│   ├── 0003_indexes.up.sql / .down.sql                # query-driven indexes
│   ├── 0004_sensor_alerts.up.sql / .down.sql          # sensor_readings, alerts
│   ├── 0005_quality_predictions.up.sql / .down.sql    # quality_checks, prediction_log, outcome_feedback
│   ├── 0006_qr_hash_processing.up.sql / .down.sql    # qr_events.prev_hash/hash/evidence_hash; processing_metrics.kitchen_id; surplus.batch_code
│   ├── 0007_audit_diversion.up.sql / .down.sql        # audit_log, diversions
│   └── 0008_mobile.up.sql / .down.sql                # refresh_tokens, device_tokens, client_event_id/client_ts (D22, D24)
├── seeds/               # idempotent (ON CONFLICT DO NOTHING), FK order
│   ├── 01_users.sql  02_kitchens.sql  03_recipients.sql
│   ├── 04_meals_attendance_production.sql   # 60+ days
│   ├── 05_waste_surplus.sql  06_matches_routes.sql
│   ├── 07_qr_events.sql      # ≥2 full, valid hash chains (generated by cmd/seedcheck, committed)
│   ├── 08_processing_metrics.sql # 30 days, 2 injected anomalies
│   ├── 09_sensor_readings.sql    # normal + 1 excursion
│   ├── 10_quality_checks.sql  11_devices.sql   # 11: two demo FCM tokens (stub strings)
├── scripts/  reset_db.sh  backup.sh  restore.sh  export_training_data.py
├── views/    v_daily_waste.sql  v_impact_summary.sql  v_training_set.sql  # read models
└── tests/    covered by backend Go suite: migrations up/down, constraints, seed minimums,
              hash-chain verify of seeded batches, test_mobile_constraints
```
Rules: no table rename without CONTRACT CHANGE; migrations append-only; `make reset` must finish < 60 s; hash chains in seeds are generated by `backend/cmd/seedcheck` (Go, D30) and committed — never hand-written SQL.
